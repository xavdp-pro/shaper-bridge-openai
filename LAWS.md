# Laws

1. The human–AI tandem owns intention and mandate. A stored context, received
   message or transport credential does not enlarge an action's authority.
2. Each action carries an immutable identity, mandate reference, explicit rights
   and jurisdiction. The adapter checks these against its actual capabilities
   and session ceiling. Unsupported rights are refused before invoking an engine.
3. Context preparation does not start generation. Loading history is distinct
   from launching a run. Continuing a session and starting a fresh prepared
   session retain distinct identities and attributable lineage.
4. Model, context revision, session identity, invocation identity and provider
   identity remain distinct. Preserve all continuity items required by an engine;
   declare portable visible-history replay separately from native engine resume.
5. Owned durable application state belongs in the instance's private MariaDB.
   Partition by actual need. Preserve transactional history, idempotent attempts,
   source/result references, failure states and explicit recovery decisions.
6. A repeated invocation identity reconciles the same attempt. It does not repeat
   a provider action. Uncertain acceptance remains visible for reconciliation.
7. Rights are enforced by mechanisms, not prompt wording. A logical scope over
   supplied context does not imply a filesystem or network security boundary.
   Acting profiles declare and enforce their actual tools and resource controls.
8. Provider credentials and private working material remain outside public
   mental sources. Realization code and private lab records have distinct owners.
9. Return a useful result or precise refusal and stop. The bridge neither invents
   successor missions nor renews agent exchanges, review loops or scheduled work.
10. Source contracts, selected realizations, installed instances and measured
    outcomes retain their respective identities. Evaluate changed boundaries
    proportionately and preserve unrelated work.
